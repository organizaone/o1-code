# agents-defaults → o1-code product: adoption study

Date: 2026-09-26. Read-only study. Scope: what from `agents-defaults` (21 files) could ship **inside the
product** so every user's agent benefits. The repository-governance use (copies in `docs/guides/` and
`.claude/skills/autorun`) is out of scope and already done.

## 4. Skip, and why

| Item                                                                                                | Reason                                                                                                                                                |
| --------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------- |
| `AUTORUN`/`HALT` tokens, acknowledgement line, `ops/` control files, internal roles                 | `/goal` already provides trigger, visible status, journaled state, budgets and an independent verifier; a second autonomy mode would compete with it. |
| Deviations-section convention and drift check                                                       | Governs copying guides between repos, not end-user agent behaviour.                                                                                   |
| `BACKLOG.md` as a file                                                                              | Meta-repository intake; only three items are mined into the prompt.                                                                                   |
| Opinionated workflow rules ("don't default to simplest", 5-file approval stop, mandatory interview) | Contradict the current prompt's scope-discipline and auto-mode design; better left to a user's own rules.                                             |
| Verb-based commit format and one-bump-per-task as defaults                                          | Personal conventions; the product should detect and follow a repo's existing style.                                                                   |
| VERSIONING release flow                                                                             | CI-specific, not agent behaviour.                                                                                                                     |
| BACKEND-JAVA, FRONTEND-MOBILE, PERSISTENCE-LOCAL (standalone), PERSISTENCE-SUPABASE in core         | Niche and version-volatile; pinned majors (Spring 3, Expo SDK, pnpm 11, TS 6) would rot inside a released product. Possible community extensions.     |
