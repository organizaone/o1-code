# Runtime documentation inventory: o1-code

Survey of 2026-09-26, branch `limpeza` (HEAD `ec5a84f` plus uncommitted work), read-only. Build evidence:
`npm run build -- --cli-only` (exit 0), `npm run bundle` (exit 0), `npm run prepare:package` (exit 0),
`npm pack --dry-run` in `dist/`: **1072 entries, 28.0 MB packed, 98.4 MB unpacked**. `node dist/cli.js --version` prints `0.1.0`.

Question answered: which documentation-like files (1) ship in a distributed artifact and (2) the app reads at run time,
through which code path, for which feature. Then: what the app reads from the user's machine, which doc URLs it shows,
which tests read docs, and a verdict per file of `docs/users/**` and `docs/developers/**`.

## Five facts that decide the question

1. **All of `docs/users/` ships and is read at run time.** `scripts/copy_bundle_assets.js:289-296` copies the whole
   directory, unfiltered, to `dist/bundled/qc-helper/docs/` (60 files, 1.26 MB; identical file set to `docs/users/`,
   `_meta.ts` and the preset JSON included). `scripts/prepare-package.js:74` refuses to package without it. The bundled
   `qc-helper` skill (`packages/core/src/skills/bundled/qc-helper/SKILL.md`) tells the model to `read_file` those docs
   relative to its base directory, which `packages/core/src/tools/skill.ts:945-946` hands it. Its index names 44 paths;
   all 44 exist. Deleting or renaming a `docs/users` file changes what the product answers, and a file named in the index
   must also be removed from `SKILL.md` lines 21-100.
2. **Nothing under `docs/developers/` ships or is read by the app.** No bundle, no VSIX, no SDK tarball carries it; no
   source reads it; the app shows no URL into it. Twelve of its files are pinned by two contract tests in `packages/cli`
   (`rest-integration-docs-contract.test.ts`, `capabilities-docs-contract.test.ts`); the other 29 are read by nothing.
3. **No doc text is compiled into JavaScript.** No `.md`/`.txt` import, no esbuild text loader, no Vite `?raw`. A probe of
   the first prose line of all 107 Markdown files under `docs/users`, `docs/developers` and the bundled skills found none
   of them in `dist/cli.js`, `dist/chunks/*` or `dist/web-shell/assets/*`. Only path and URL strings are embedded.
4. **The app links to five `docs/users` files by URL or path, all on GitHub `main`.** `tos-privacy.md` (auth dialog, CLI
   and Web Shell), `configuration/settings.md` (Arena dialog, with a broken anchor), `features/dual-output.md` (a setting
   description), `conversations-recovery.md` (a debug log line), `extension/getting-started-extensions.md` (the shipped
   starter template's README). `/docs` and the help screen link to the `docs/` tree as a whole. `brand.json` holds only
   `identity.repoUrl`, and no runtime code reads it: every URL is a hardcoded literal.
5. **The VS Code extension re-ships the whole CLI `dist/`, docs included**; the SDK does not. `vscode-ide-companion`
   copies the root `dist/` to `dist/o1-code-cli/` (`scripts/copy-bundled-cli.js:55`), and `.vscodeignore` keeps `dist/**`,
   so the VSIX carries `bundled/qc-helper/docs/` too. `sdk-typescript/scripts/bundle-cli.js:74-90` copies only `cli.js`,
   `chunks`, `vendor` and `locales`: the SDK's embedded CLI has **no bundled skills at all** (no `/review`, no
   `qc-helper`) and no extension templates.

## 2. How the shipped docs are reached

- **Bundled skills directory.** `SkillManager` sets `bundledSkillsDir = resolveBundleDir(import.meta.url)/bundled`
  (`packages/core/src/skills/skill-manager.ts:110-113`). In the bundle that is `dist/bundled/`; in dev it is
  `packages/core/src/skills/bundled/`, where `scripts/dev.js:37-50` creates the gitignored symlink
  `qc-helper/docs -> docs/users` (`.gitignore:92-93`). Precedence is project > user > extension > bundled, so a user
  skill named `qc-helper` shadows it; safe mode loads bundled skills only (`:456-459`).
- **Skill body to model.** On activation `skill.ts:945-946` builds the LLM content with the skill's base directory; the
  skill tool description (`skill.ts:77`) tells the model to resolve referenced files from that directory. The
  `qc-helper` frontmatter allows `read_file`, `edit_file`, `grep_search`, `glob`, `read_many_files`.
- **qc-helper index coverage.** 44 indexed paths, all present. Present but **not indexed** (reachable only if the model
  globs or greps): `extension/agent-plugins.md`, `features/agent-board.md`, `features/context-cost.md`,
  `features/cross-session-protocol.md`, `features/goals.md`, `features/multi-agent-coordination.md`,
  `features/output-styles.md`, `features/rules.md`, `features/terminal-images.md`, `features/omni-fixed-policies-preset.json`.
  The six `_meta.ts` files ship too and serve no purpose there.
- **Extension templates.** `extensions new` copies `dist/examples/<template>` into the user's new extension
  (`cli/src/commands/extensions/new.ts:25-133`); those files then become the user's own context file, agent, command and
  skill, loaded by the readers in §3.
- **Direct `readFileSync` of a shipped skill.** Only `workflow-authoring-skill.ts:83` (the workflow tool's reference).
  The `/review` CLI subcommands do not read `SKILL.md`; they only mirror its contracts, and `stale-bundle.ts` reads
  `review-sources.sha256`.

## 7. Surprises

1. **`NOTICE` does not ship.** `prepare-package.js:108` copies only `README.md` and `LICENSE`, and `NOTICE` is not in
   `files`. AGENTS.md makes `NOTICE` the global Apache-2.0 §4(b) modification notice, and §4(d) asks a redistribution to
   carry the `NOTICE` of the work. The npm tarball has none; the VSIX carries `NOTICES.txt` (third-party licences), which
   is a different file.
2. **The whole `docs/users` tree is product payload, including files that are useless there**: six `_meta.ts`
   navigation files and a 242-line policy preset JSON. The copy is unfiltered, and `prepare-package.js:74` fails the
   package when the directory is missing, so removing `docs/users` entirely breaks the release, not only `qc-helper`.
3. **The SDK's embedded CLI has no bundled skills.** `bundle-cli.js` omits `bundled/` and `examples/`, so `/review`,
   `qc-helper` and `extensions new` templates are missing when the CLI runs from `@organizaone/o1-code-sdk`.
4. **`bundled/loop/*.ts` sources ship** (three TypeScript files, 45 KB) because the copier filters only test files.
5. **Doc links follow `main`.** Every in-app URL is a hardcoded `(repo)/blob|tree/main/…` literal; `brand.json`'s
   `repoUrl` is read only by build scripts (`prepare-package.js:347`, `release-script-utils.js:24`). Moving or deleting a
   linked doc breaks installed releases immediately.
6. **Broken targets today**: `/bug` (CLI and Web Shell) points to a missing `bug_report.yml` template; the Arena dialog's
   `#modelproviders` anchor does not exist; the i18n key `docs/keyboard-shortcuts.md` is unused and names a missing path.
7. **Context discovery accepts only `O1CODE.md`, `AGENTS.md`, `O1CODE.local.md`.** No `CLAUDE.md`/`QWEN.md`/`GEMINI.md`;
   `context.fileName` replaces the defaults instead of extending them. `system.md` is resolved against the working
   directory. Plan files are written but never read back; `~/.o1-code/memory.md` is dead.
8. **The doc contract tests do not run on pull requests.** They run in the manually dispatched CI `full` job and in local
   `npm run test`; a doc deletion that breaks them passes the `fast` job.
